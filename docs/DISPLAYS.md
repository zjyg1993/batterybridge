# 外接显示器 DDC 控制（0.8.2 Preview）

## 当前能力与系统边界

| 入口 | 当前行为 |
| --- | --- |
| 设备扫描 | 在键鼠列表中同时发现外接物理显示器，读取系统型号、厂商、产品、序列及显示 UUID |
| 应用内亮度 | 读取并设置 MCCS VCP `0x10`，控制硬件背光 |
| 状态栏菜单 | 每台显示器直接显示亮度、音量百分比并提供独立滑块；与主界面共用 DDC 校验、写后回读及失败停用逻辑，不依赖媒体键映射或辅助功能权限 |
| 应用内音量 | 独立探测 VCP `0x62`，控制显示器扬声器音量 |
| 映射开关 | 每台显示器独立保存，默认关闭；控制媒体键转发及内建屏幕亮度同步，不影响应用内手动调节 |
| 系统亮度键 | 桌面 Mac 选择指针所在显示器；MacBook 保留内建屏幕原行为并同步其亮度变化 |
| 系统音量键 | 仅当前默认 HDMI / DisplayPort 输出与显示器型号唯一匹配、且输出没有可写原生音量属性时转发 |
| 静音键 | 以 VCP 音量零值模拟；记忆本次运行静音前数值，再按恢复；启动时已为零且无恢复值时不猜测音量 |
| 已有原生亮度滑块 | MacBook 有在线内建屏幕时，跟随其亮度变化，包括控制中心及自动亮度；首次发现和唤醒仅建立基线，不覆盖外屏当前值 |
| Mac mini 原生控制中心亮度滑块 | **未接入**，不会因 DDC 通道存在而新增系统滑块 |
| 无原生音量属性的 HDMI 输出系统滑块 | **未接入**；当前未安装 HAL 音频代理驱动，也不改变默认音频输出 |

DDC/CI 是显示器通信协议，不是 macOS 控制中心设备注册协议。系统没有公开接口，让普通用户态应用为任意 HDMI 显示器增加原生亮度滑块或给现有只读音频设备增加音量属性。完整原生滑块接入需要另行实现、验证系统显示集成及 Core Audio 音频代理，不能以媒体键或应用内滑块代替其完成状态。此版不宣称完成原生滑块桥接。

通用方案不限品牌，不依赖型号白名单；以标准 VCP 的有效实际回复判断各项能力，不以可能不完整的 capabilities 声明作为唯一依据。扫描只读，不通过修改用户设置试探可写性；首次用户调节后再以回读验证是否生效。

Dell S2725QS 为已反馈可用的型号，官方手册包含 DDC/CI 和音量设置；具体 VCP 功能、HDR 下的限制、线缆与 Mac 端口能力仍以实机响应为准。不将 S2725QS 与 S2725SQ、S2721QS 或 S2725QC 混为同型号。

## 通信和设备匹配

- Apple Silicon 动态加载 `IOAVServiceCreateWithService`、`IOAVServiceReadI2C` 和 `IOAVServiceWriteI2C`；Intel 使用 `IOFramebuffer` / `IOI2CInterface`。二者均编译，尚未实机确认。
- DDC 7 位地址 `0x37`，源地址 `0x51`，读取 / 设置 VCP 操作码为 `0x01` / `0x03`。IOAVService GET 请求校验的差异参考 MonitorControl 的公开实现；无第三方二进制依赖。
- 仅探测外接非 Apple 显示器。按注册表位置、型号和可用的厂商 / 产品 / 序列号约束匹配。同时检查文本序列号；已知位置冲突时不退回同型号匹配，相同序列号可在无型号名时识别。多个显示器无法唯一对应通道时禁用控制，不按枚举顺序猜测。
- 单个外屏且只有一个外部通道、通道无型号信息时允许唯一对应。相同型号的多台屏若缺少可区分序列或位置，保持不可用。
- 所有总线操作在独立串行队列执行，命令间至少间隔 50ms；读取最多尝试 3 次，快速滑块 / 按键变更合并为最新目标。
- 回复检查长度、地址、校验、操作码、结果、功能码与范围；最大值从显示器读取，不假定为 100。读取超时或异常不会显示为 0%。
- 每次写入后回读确认，允许一个硬件单位的舍入误差。首次回读仍为旧值时，延迟 100ms 再读一次，不重复写入。设备忽略写入、HDR 限制、写入或回读失败时显示错误，并停用该功能；自动扫描不会解除此停用状态，用户点击显示器刷新或“刷新全部”重新只读探测后才可再试。音量失效同时阻止应用内音量、媒体音量键与静音转发，亮度不受音量失效影响。
- 每 30 秒重新发现，显示器插拔 / 模式切换、系统及屏幕唤醒后立即重查。扫描期间保留上一份可见列表并禁用调节，结果完成后一次性更新；显示器不提供右键删除；本次未发现的已知显示器保留为“未连接”，移除旧读数对应的控制能力，不从列表消失。拓扑变化取消待执行写入，旧身份不用于新连接。
- 启动扫描只读，不写亮度或音量，不切换输入源、供电、显示模式或音频路由。

## 权限与使用

1. 在显示器 OSD 中启用 DDC/CI；优先直连 Mac。DisplayLink、部分扩展坞、KVM、HDMI 端口可能无法透传。
2. 启动应用，点击“刷新全部”。设备列表出现实际型号；亮度、音量各自有有效读数且没有写入失败停用状态才开放滑块。未读取到音量时，音量滑块禁用并提供不可用提示，媒体音量与静音不会转发。
3. 应用内调节不需辅助功能权限。需使用媒体键或内建屏幕亮度同步时，开启显示器行的“媒体键与亮度同步”；媒体键还需点击“授权快捷键…”允许辅助功能。关闭映射立即停止此显示器的转发，并取消尚未执行的转发命令；已在传输的 DDC 命令无法撤回。选择按显示器身份保存，重启后保留。
4. 音量键只跟随当前默认的、名称唯一匹配的 HDMI / DP 音频输出；切到耳机、蓝牙或内建扬声器后交回系统。名称无法匹配时仍可用设备行滑块。
5. 关闭主窗口仍在后台运行；退出时移除事件监听、定时器和待执行写入。显示器保留最后实际设定值。

媒体键事件仅处理亮度、音量及静音，不保存输入事件。调节反馈为 DeviceBridge 自己的提示面板，不宣称为原生控制中心 OSD。

### 快捷键权限与原生控制中心

“媒体键与亮度同步”仅启用表中已实现的入口，不能为 Dell HDMI 输出新增原生亮度或音量滑块。截图中系统滑块为灰色与 DDC 应用内控制有效可以同时发生；辅助功能授权不改变此系统能力。

权限按钮按当前进程的实时结果更新：辅助功能已授权，或默认模式的可过滤媒体键监听已经成功建立且仍有效时，隐藏“授权快捷键…”。仅有输入监控的预检结果不会被视为已具备拦截权限；程序会尝试建立真实监听以确认。每两秒及从系统设置返回时重新检查，不保存“已授权”布尔值，也不会因设备列表内容未变化而跳过按钮更新。

2026-11-16 本次终端执行环境只读检查得到在线显示器数 0、默认音频设备 ID 0，不能用于确认截图所在 GUI 会话的权限或硬件状态。新增测试覆盖授权生效、监听已工作、权限撤销及返回应用时的按钮变化；不将模拟测试视为原生控制中心桥接验证。

原生 HDMI 音量路径还缺少虚拟输出驱动、音频转发、默认输出与退出恢复及实际安装验证；当前没有安装此类驱动。Apple 的 [Audio Server Plug-in 示例](https://developer.apple.com/documentation/coreaudio/creating-an-audio-server-driver-plug-in)提供虚拟音频设备基础，但并不提供 DDC 或亮度桥接。本版不宣称已解决原生控制中心滑块。


### 0.8.2 状态栏设备菜单

- 2.4G 键鼠仅显示连接、电量与充电状态，无调节控件、映射开关或删除操作。失联或电量过期时不将旧百分比显示为当前电量。
- 显示器亮度、音量各自有菜单滑块。连续拖动复用串行队列合并命令，写入后按实际回读更新百分比；菜单打开本身不写硬件。
- 菜单打开时每 250ms 更新已有设备行，不重建正在交互的滑块；拖动过程中保留滑块位置，避免后台读数拉回。断开、扫描或功能失效时及时禁用对应控制；菜单关闭后取消界面刷新定时器。显示器探测定时器也在菜单追踪模式下继续运行。
- 保留“显示主界面”和“退出 DeviceBridge”。这是 DeviceBridge 自己的状态栏菜单，原生控制中心接入状态不变。
- 回归覆盖键鼠只读、菜单滑块功能码及显示器身份路由、关闭映射仍可手动调节、音量不可用 / 断开禁用、菜单刷新和拖动不跳动、关闭菜单释放定时器；浅色和深色菜单设备视图均完成离屏渲染检查。硬件调节仍需真实 GUI 会话验证。
